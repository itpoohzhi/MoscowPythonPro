# Спека EARS: Фильтрация ссылок по тегам (LINK-43)

**task_id:** LINK-43
**Дата:** 2026-10-29
**Статус:** approved (архитектор одобрил волну 1 с миграцией)

## Контекст
Модель `Link` не имеет тегов. Фича добавляет `tags` к ссылкам и фильтр списка `GET /api/v1/links?tag=<тег>`.
Хранение: колонка `tags JSON NOT NULL DEFAULT '[]'` в таблице `links`.
Волна 1: миграция Alembic + модель. Волна 2: схемы/сервис/репозиторий/роутер/тесты (≤ 7 файлов).

## Требования

- [REQ-001] Система ДОЛЖНА принимать при создании ссылки список тегов через поле `tags` схемы `LinkCreate`.
- [REQ-002] Система ДОЛЖНА хранить теги связи в колонке `tags` таблицы `links` в виде JSON-массива строк.
- [REQ-003] КОГДА создана ссылка без тегов, система ДОЛЖНА сохранить пустой массив `tags` и старый контракт ответа без изменений кроме добавляемого поля.
- [REQ-004] КОГДА клиент запрашивает `GET /api/v1/links?tag=<тег>`, система ДОЛЖНА возвращать только те ссылки, у которых `tags` содержит этот тег, в порядке «новые первыми».
- [REQ-005] КОГДА клиент запрашивает `GET /api/v1/links?tag=<тег>` и не существует ни одна ссылка с таким тегом, система ДОЛЖНА вернуть `200` с пустым списком.
- [REQ-006] ЕСЛИ тег не соответствует паттерну `^[a-z0-9_-]{2,32}$`, ТО система ДОЛЖНА отклонить запрос со статусом `422`.
- [REQ-007] ЕСЛИ список тегов содержит более 10 элементов, ТО система ДОЛЖНА отклонить запрос со статусом `422`.
- [REQ-008] ЕСЛИ список тегов пуст или отсутствует, ТО система ДОЛЖНА сохранить ссылку с пустым массивом (фича обратно совместима).
- [REQ-009] ПОКА отфильтрованный список не содержит искомый тег, система ДОЛЖНА не возвращать в выборку ссылки без этого тега (включая невидимые для фильтра пустые массивы).

## Ограничения
- Замороженные пути не изменяются (`app/main.py`, `app/core/config.py`, `app/core/security.py`).
- Старые поля ответов эндпоинтов не переименовываются и не удаляются (новое поле `tags` добавляется со значением по умолчанию).
- Репозиторий: новый метод на SQLAlchemy; сервис не импортирует fastapi.
- Дубли тегов в списке создателя допустимы и сохраняются как есть (FU-002): фильтр по тегу от этого не зависит.
- Пустой query-параметр `?tag=` отклоняется статусом `422` (пустое значение не совпадает с паттерном тега; FU-003).
- Осознанная асимметрия среза LINK-43 (FU-004): фильтр `?tag=` добавлен только в `GET /api/v1/links`;
  плоский `GET /links`, bulk-создание и `LinkStats` теги не принимают/не отдают — регистрируется как контекст
  в `docs/module-map.md` и follow-up в `.planning/STATE.md`.
