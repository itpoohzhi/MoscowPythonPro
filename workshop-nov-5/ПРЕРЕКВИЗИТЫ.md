## OpenCode CLI и глобальная конфигурация

Установи OpenCode CLI официальным установщиком, затем проверь бинарник:

```bash
cd ~ 2>/dev/null || cd "$HOME"
command -v opencode >/dev/null 2>&1 || curl -fsSL https://opencode.ai/install | bash
export PATH="$HOME/.opencode/bin:$HOME/.local/bin:$PATH"
opencode --version
```

💡 **Что здесь важно:** если установщик выбрал другой каталог, используй путь, который он напечатал, и повтори `opencode --version`.

Создай базовую конфигурацию. Встроенная бесплатная модель называется `opencode/glm-5.3-flash-free`; после авторизации в OpenCode Go можно выбрать `opencode-go/glm-5.3-flash`. Авторизацию провайдеров выполняй через `opencode auth login`, не записывай ключи в JSON.

> [!IMPORTANT]
> `opencode auth login` требует интерактивный терминал (TTY): запускай команду в обычном Terminal или PowerShell, чтобы выбрать провайдера и пройти вход. Не запускай её в неинтерактивном E2E-раннере.

```bash
cd ~ 2>/dev/null || cd "$HOME"
mkdir -p ~/.config/opencode
cat > ~/.config/opencode/opencode.json <<'EOF_OPENCODE_CONFIG'
{
  "$schema": "https://opencode.ai/config.json",
  "model": "opencode/glm-5.3-flash-free",
  "small_model": "opencode/glm-5.3-flash-free"
}
EOF_OPENCODE_CONFIG
opencode auth login
```

💡 **Что здесь важно:** `~/.config/opencode/opencode.json` хранит настройки модели, а секреты остаются в защищённом хранилище OpenCode.

# 1. Системное окружение

## 1.1. Homebrew (только macOS)

Ставим менеджер пакетов macOS. Через него устанавливаются Docker Desktop, git и VS Code.

Пользователи Linux и Windows (WSL): шаги **1.1.1–1.1.4 пропустите**, git и окружение ставятся в шаге 1.2.4.

### 1.1.1. Установка Homebrew

> [!IMPORTANT]
> Установщик Homebrew требует интерактивный терминал (TTY): он ждёт Enter и может запросить пароль администратора. Запускайте его в штатном Terminal, а не в неинтерактивном раннере.

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Скачиваем и устанавливаем Homebrew. Сначала установщик выведет список создаваемых каталогов и строку `Press RETURN/ENTER to continue or any other key to abort` — нажмите клавишу **Enter**. Любая другая клавиша отменит установку. Затем установщик запросит пароль администратора Mac: вводите пароль разблокировки компьютера (символы при вводе в терминале скрыты — это штатное поведение).

**Ожидай:** в конце строку `Installation successful!` или `already installed`. Если терминал вернул приглашение без `Installation successful!` — была нажата не та клавиша, повторите команду. При таймауте сети (`curl: (7)`) включите VPN и повторите.

### 1.1.2. Apple Silicon — brew в PATH

Выполняется только на компьютерах Mac с чипами Apple Silicon (M1/M2/M3/M4). Пользователи Intel Mac переходят сразу к 1.1.3. Если сомневаетесь в типе процессора, выполните `uname -m`: вывод `arm64` означает чип Apple Silicon, `x86_64` — Intel.

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
```

Прописываем запуск окружения Homebrew в автозагрузку профиля zsh.

**Ожидай:** пустой вывод.

```bash
eval "$(/opt/homebrew/bin/brew shellenv)"
```

Активируем Homebrew в текущем окне терминала без перезапуска.

**Ожидай:** пустой вывод.

### 1.1.3. Intel Mac — brew в PATH

Выполняется только на компьютерах Mac с процессорами Intel (`x86_64`). Компьютеры Apple Silicon этот шаг пропускают.

```bash
echo 'eval "$(/usr/local/bin/brew shellenv)"' >> ~/.zprofile
```

Прописываем пути Intel-версии Homebrew в автозагрузку.

**Ожидай:** пустой вывод.

```bash
eval "$(/usr/local/bin/brew shellenv)"
```

Активируем пути в текущем терминале.

**Ожидай:** пустой вывод.

### 1.1.4. Проверка Homebrew

```bash
brew --version
```

Проверяем доступность утилиты brew.

**Ожидай:** строку вида `Homebrew 4.x.x` / `Homebrew 7.x.x+`. Если отображается `command not found` — вернитесь к шагу 1.1.2 (для M-чипов) или 1.1.3 (для Intel) и откройте новое окно терминала.

## 1.2. Docker & Docker Compose

Docker необходим для запуска локальной базы данных PostgreSQL 17 в изолированном контейнере.

### 1.2.1. macOS: Установка Docker через Homebrew

> [!IMPORTANT]
> `brew install --cask docker` может запросить пароль администратора. Выполняйте команду в интерактивном Terminal (TTY), а не через неинтерактивный раннер.

```bash
brew install --cask docker
```

Загружаем и устанавливаем официальное приложение Docker Desktop.

**Ожидай:** строку `docker was successfully installed!`. При сбое сети включите VPN и повторите.

### 1.2.2. macOS: Запуск приложения Docker

```bash
open -a Docker
until docker info >/dev/null 2>&1; do sleep 2; done
mkdir -p ~/.docker/cli-plugins && [ -e ~/.docker/cli-plugins/docker-compose ] || ln -sf /Applications/Docker.app/Contents/Resources/cli-plugins/docker-compose ~/.docker/cli-plugins/docker-compose 2>/dev/null || true
```

Запускаем Docker Desktop в фоновом режиме.

**Ожидай:** пустой вывод. В строке меню macOS вверху экрана появится иконка кита. При первом старте Docker Desktop запросит подтверждение соглашения (кнопка «Accept») и системные привилегии администратора. Дождитесь, пока иконка кита перестанет мигать.

### 1.2.3. macOS: Проверка работы демона Docker

```bash
docker ps
docker compose version
```

**Ожидай:** заголовок таблицы с колонками `CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES`. Если терминал сообщает `Cannot connect to the Docker daemon` — Docker Desktop ещё загружается, подождите 10–15 секунд и повторите команду.

### 1.2.4. Linux и Ubuntu в WSL: Установка пакетов Docker Engine

В Ubuntu все действия выполняются внутри терминала дистрибутива:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg git build-essential python3-dev
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu ${VERSION_CODENAME} stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

**Ожидай:** завершение установки пакетов без сообщений об ошибках. При таймауте загрузки ключа включите VPN.

### 1.2.5. Linux и Ubuntu в WSL: Права пользователя и служба Docker

```bash
sudo usermod -aG docker $USER
sudo service docker start || sudo systemctl start docker
```

Предоставляем пользователю права запуска контейнеров без префикса `sudo` и запускаем службу демона Docker.

**Ожидай:** сообщение `* Starting Docker: docker [ OK ]` или тихий старт службы.

### 1.2.6. Linux и Ubuntu в WSL: Проверка прав запуска контейнеров

Закройте окно терминала Ubuntu и откройте его заново (это необходимо для применения группы `docker`). В новом окне выполните:

```bash
docker ps
```

**Ожидай:** заголовок таблицы контейнеров без ошибки `permission denied`.

### 1.3.4. Linux и Ubuntu в WSL: Git и базовые пакеты

```bash
sudo apt-get update && sudo apt-get install -y git curl ca-certificates build-essential
git config --global core.autocrlf input
```

В Ubuntu внутри WSL устанавливаем Git и базовые инструменты, но не пакет `code`. VS Code устанавливается на Windows-хосте в шаге 1.3.5, а расширение WSL предоставляет команду `code` внутри Ubuntu. Настройка `core.autocrlf input` не даёт Git преобразовать окончания строк bash-скриптов `.sh` в CRLF.

**Ожидай:** завершение установки без ошибок и пустой вывод от `git config`.

### 1.3.5. Windows (хост): установка VS Code и расширения WSL

Если WSL ещё не установлен, сначала откройте PowerShell **от имени Администратора** и выполните:

```powershell
wsl --install
```

Команда включает компоненты WSL и `VirtualMachinePlatform` и ставит Ubuntu. После установки перезагрузите компьютер и дождитесь первого запуска Ubuntu (там нужно создать имя пользователя и пароль).

> [!WARNING]
> Если Windows 11 запущена внутри Parallels Desktop или другой Hyper-V VM и `wsl --install` завершается ошибкой `HCS_E_HYPERV_NOT_INSTALLED` (`0x80370102`), гостевой системе недоступна аппаратная виртуализация. Выберите один маршрут:
> 1. Остановите VM и на Mac-хосте включите Nested Virtualization: `prlctl set "Windows 11" --nested-virt on`, затем снова запустите Windows и повторите `wsl --install`.

## 2.3. Защита `.env` от попадания в Git + первый коммит-чекпоинт

В репозитории `.env` может быть случайно зафиксирован или отслеживаться Git. Если вписать реальный API-ключ и затем сделать коммит или переключить ветку, секреты попадут в историю контроля версий или затрутся. Чиним это немедленно до внесения любых ключей.

### 2.3.1. Дописать .gitignore

```bash
cd ~/work/MoscowPythonPro/workshop-nov-5
grep -qxF '.env' .gitignore || printf '%s\n' '.env' '.env.*' '!.env.example' >> .gitignore
```

Говорим Git полностью игнорировать `.env` и его производные, но оставлять публичный шаблон `.env.example`.

**Ожидай:** пустой вывод.

### 2.3.2. Убрать .env из индекса Git

```bash
cd ~/work/MoscowPythonPro/workshop-nov-5
git rm --cached -f --ignore-unmatch .env
```

Git перестаёт отслеживать файл `.env`, при этом сам файл на диске сохраняется.

**Ожидай:** вывод `rm 'workshop-nov-5/.env'` или тишина, если файл ранее не находился в индексе.

### 2.3.3. Настройка автора и первый коммит-чекпоинт

В свежем клоне `git commit` может завершиться ошибкой, если не указаны имя и почта автора. Зададим их для учебных коммитов:

**Ожидай:** строки `M .gitignore` и/или `D .env`. В выводе **не должно** быть строки `A .env`.

Зафиксируем защиту секретов в ветке:


**Ожидай:** строку `chore: перестать трекать .env` и количество изменённых файлов либо пустой вывод, если защита уже была зафиксирована ранее.

## 2.7. Запуск локальной базы данных PostgreSQL 17 в Docker

Сервис сокращения ссылок требует работающей реляционной СУБД с поддержкой драйвера `psycopg`.

### 2.7.1. Запуск контейнера db

```bash
cd ~/work/MoscowPythonPro/workshop-nov-5
if [ "$(uname -s)" = Darwin ]; then
  mkdir -p ~/.docker/cli-plugins && [ -e ~/.docker/cli-plugins/docker-compose ] || ln -sf /Applications/Docker.app/Contents/Resources/cli-plugins/docker-compose ~/.docker/cli-plugins/docker-compose 2>/dev/null || true
fi
docker compose down -v 2>/dev/null || true
docker compose up -d --wait db
```

Сначала `docker compose down -v` удаляет старые контейнеры и тома (если они остались от прошлых запусков): так база стартует с чистой схемы, и начальная миграция Alembic применится без конфликтов. Затем запускаем контейнер базы данных в фоновом режиме с флагом `--wait` (команда ждет, пока база пройдет проверку работоспособности healthcheck).

**Ожидай:** строки `Container ... Created`, `Container ... Started` и `Healthy`.

### 2.7.2. Проверка доступности порта 5432 и статуса контейнера


### 2.9.3. Настройка моделей и API-ключей (OpenCode Models & Auth)

OpenCode — консольный AI-агент, которому для работы требуется доступ к языковой модели. Вы можете подключить полностью бесплатный ключ (без привязки банковской карты) либо воспользоваться корпоративным шлюзом.

#### Вариант 1. Бесплатный Google Gemini (Рекомендуется для всех участников)
Google предоставляет щедрый бесплатный тариф для разработчиков без ввода банковской карты (15 запросов в минуту, 1 млн токенов в день):
1. Откройте **[Google AI Studio](https://aistudio.google.com/app/apikey)** и нажмите **Create API key** (войдите под Google-аккаунтом).
2. Скопируйте полученный ключ.
3. Пропишите переменную окружения в терминале:
   ```bash
   export GEMINI_API_KEY="ваш_ключ_из_ai_studio"
   grep -Fq 'GEMINI_API_KEY' ~/.zprofile 2>/dev/null || echo 'export GEMINI_API_KEY="ваш_ключ_из_ai_studio"' >> ~/.zprofile
   grep -Fq 'GEMINI_API_KEY' ~/.bashrc 2>/dev/null || echo 'export GEMINI_API_KEY="ваш_ключ_из_ai_studio"' >> ~/.bashrc
   ```
Рекомендуемые модели: `google/gemini-2.5-flash` (быстрая и точная для Python и FastAPI) и `google/gemini-2.5-pro` (для сложного анализа).

#### Вариант 2. Бесплатный Groq (Сверхбыстрые Llama 3.3 и Qwen Coder)
1. Зарегистрируйтесь на **[console.groq.com/keys](https://console.groq.com/keys)** (бесплатная регистрация без карты).
2. Создайте API-ключ и добавьте его в окружение:
   ```bash
   export GROQ_API_KEY="gsk_ваш_ключ"
   grep -Fq 'GROQ_API_KEY' ~/.zprofile 2>/dev/null || echo 'export GROQ_API_KEY="gsk_ваш_ключ"' >> ~/.zprofile
   grep -Fq 'GROQ_API_KEY' ~/.bashrc 2>/dev/null || echo 'export GROQ_API_KEY="gsk_ваш_ключ"' >> ~/.bashrc
   ```
Рекомендуемые модели: `groq/qwen-2.5-coder-32b`, `groq/llama-3.3-70b-versatile`.

#### Вариант 3. Бесплатный OpenRouter (модели с суффиксом :free)
1. Зарегистрируйтесь на **[openrouter.ai](https://openrouter.ai/)** и создайте ключ.
2. Экспортируйте переменную:
   ```bash
   export OPENROUTER_API_KEY="sk-or-v1-ваш_ключ"
   ```
Доступные бесплатные модели: `openrouter/deepseek/deepseek-chat:free`, `openrouter/qwen/qwen-2.5-coder-32b-instruct:free`.

#### Вариант 4. Корпоративный шлюз воркшопа (AgentPlatform)
Если организаторы воркшопа выдали вам единый ключ доступа к выделенному шлюзу:
```bash
export AGENTPLATFORM_API_KEY="выданный_ключ"
grep -Fq 'AGENTPLATFORM_API_KEY' ~/.zprofile 2>/dev/null || echo 'export AGENTPLATFORM_API_KEY="выданный_ключ"' >> ~/.zprofile
grep -Fq 'AGENTPLATFORM_API_KEY' ~/.bashrc 2>/dev/null || echo 'export AGENTPLATFORM_API_KEY="выданный_ключ"' >> ~/.bashrc
```

#### Проверка доступности моделей

Для GLM 5.3 доступны два идентификатора: `opencode-go/glm-5.3-flash` после подключения OpenCode Go и встроенная бесплатная модель `opencode/glm-5.3-flash-free`. Перед авторизацией откройте обычный интерактивный Terminal или PowerShell (TTY) и выполните `opencode auth login`; в неинтерактивном раннере выбор провайдера не откроется.

Проверить подключение и увидеть GLM, DeepSeek или встроенную `big-pickle` можно командой:

**Ожидай:** хотя бы одну строку с `glm-5.3-flash`, `deepseek` или `big-pickle` без ошибок авторизации.
