# Правила безопасного рефакторинга

Рефакторинг улучшает внутреннюю структуру, читаемость или производительность кода **без изменения внешнего поведения**.

## 1. Главные нерушимые правила

1. **Сначала страховка тестами:** перед первым изменением убедись, что текущее поведение покрыто тестами и `uv run pytest -q` проходит с кодом `0`. Если нужного покрытия нет — сначала добавь Characterization Tests (`.agents/skills/characterization-tests/SKILL.md`).
2. **Не смешивай рефакторинг с новой функциональностью:** рефакторинг идёт отдельным коммитом / PR; публичные HTTP-контракты, схемы `app/schemas/` и семантика ошибок остаются неизменными.
3. **Маленькие обратимые шаги:** делай одно логическое преобразование за раз (выделение метода, перенос запроса в репозиторий, устранение дублирования) и прогоняй `uv run pytest -q` после каждого шага.
4. **Соблюдение слоёв и Blast Radius:** сверяйся с `.agents/agents/architecture.md` и лимитом файлов из `specs/blast-radius.json`.

## 2. Проверка силы тестов и стоп-условия

- После завершения рефакторинга проверь не только зелёный `pytest`, но и полное прохождение `uv run ruff check .`, `uv run basedpyright` и покрытия ветвлений (`--cov-branch`).
- Если тест падает на одном и том же месте **3 попытки подряд** — немедленный стоп и эскалация по `.agents/agents/error-handling.md` (severity **High**), без костылей и ослабления `assert`.
