# Правила оформления Merge Request / Pull Request

Единые требования к подготовке PR/MR в репозитории проекта (совместно с `.agents/AGENTS.md` и `.agents/skills/mr/SKILL.md`).

## 1. Предусловия до открытия PR/MR

1. Ветка актуальна относительно `main`, рабочее дерево чистое, лишние временные файлы не закоммичены.
2. Все ворота качества локально вернули код `0`:
   - `uv run ruff check .`
   - `uv run ruff format --check .`
   - `uv run basedpyright`
   - `uv run pytest -q`
   - при изменениях архитектуры/доков — `uv run python tools/verify_techlead_gate.py`.
3. Соблюдён Blast Radius задачи и таблица «Язык общения» из `.agents/AGENTS.md` (тэг/scope на английском, описание на русском, префикс `[agent]` / `[assisted]` / `[manual]`).

## 2. Обязательная структура описания PR/MR

- **Заголовок:** Conventional Commits (`feat(links): ...`, `fix(billing): ...`, `refactor(services): ...`).
- **Зачем:** какая задача или дефект решается (ссылка на тикет / спеку `specs/`).
- **Что изменено:** короткий список ключевых изменений по слоям (`API`, `Service`, `Repository`, `Migrations`, `Tests`, `Docs`).
- **Как проверено:** точные выполненные команды и фактический результат (количество тестов, покрытие ветвлений, `alembic check`).
- **Риски и откат:** совместимость API/БД, шаги отката при проблемах.

## 3. Запрет авто-слияния

- Агент готовит ветку, описание и проверки, но **не выполняет auto-merge без явного одобрения человеком (Human-in-the-Loop)**.
