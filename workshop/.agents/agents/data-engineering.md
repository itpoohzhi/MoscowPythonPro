# Правила Data Engineering и работы с БД

Декларативные правила проектирования схем данных, миграций, аналитических таблиц и выгрузок в проекте `linksvc` (PostgreSQL 17, SQLAlchemy 2.0 async, Alembic, Pydantic v2).

## 1. Схемы БД и обратимые миграции Alembic

- Любое изменение ORM-моделей в `app/models/` сопровождается миграцией в `alembic/versions/`.
- У каждой миграции обязана быть рабочая функция `downgrade()` (пустой `pass` запрещён).
- Всегда проверяй полный цикл на реальном PostgreSQL 17:
  1. `uv run alembic upgrade head`
  2. `uv run alembic downgrade -1`
  3. `uv run alembic upgrade head`
  4. `uv run alembic check` (должно вернуть `No new upgrade operations detected.`)
- Индексы и ограничения (`NOT NULL`, `UNIQUE`, `CHECK`, `FOREIGN KEY`) задаются явно в модели и в миграции; для частых фильтров и сортировок добавляй составные индексы.

## 2. Идемпотентность, стриминг и защита от OOM

- Повторный запуск загрузки, пересчёта или миграции данных не должен создавать дубликаты и ломать агрегаты (`ON CONFLICT DO NOTHING` / `DO UPDATE`, детерминированные ключи).
- Запрещено выгружать неограниченные таблицы в память целиком (`scalars().all()` на всём наборе данных): используй `LIMIT`/`OFFSET` или keyset-пагинацию и потоковую обработку батчами.
- Все конфигурации пайплайнов и подключений валидируются через Pydantic (`pydantic-settings`), секреты берутся только из окружения / `.env`, никогда не хардкодятся в коде и тестах.

## 3. Аналитические запросы и защита данных

- Для аналитических проверок и MCP-инспекции БД используется строго режим Read-Only (`SELECT` с явным `LIMIT`).
- В логи и аналитические витрины не пишутся секреты, токены и сырые PII без явной политики маскирования.

## §10.4. Definition of Done (DoD)

Задача по данным / схеме БД / пайплайну считается выполненной только когда подтверждены все пункты:

- [ ] Миграция или пайплайн проверены локально на реальной СУБД / локальной эмуляции (не на моках).
- [ ] Для миграций Alembic пройден полный цикл `upgrade head → downgrade -1 → upgrade head → alembic check` с кодом возврата `0`.
- [ ] Повторный прогон идемпотентен (не плодит дубликаты и не ломает состояние).
- [ ] Конфигурация (Pydantic-схема / переменные окружения) описана и прокомментирована в коде и документации домена (`docs/domains/`).
- [ ] Ворота качества зелёные: `uv run ruff check .`, `uv run basedpyright`, `uv run pytest -q`.
