# Правила аварийных исправлений (Hotfix)

Hotfix применяется только к критическому инциденту в `main`, который нельзя откладывать до планового релиза.

## 1. Жёсткие ограничения

1. **Базовая ветка — только `main`:** `git checkout main && git checkout -b hotfix/<KEY>-<short-description>`.
2. **Минимальный Blast Radius:** меняй только строки, напрямую устраняющие инцидент. Попутный рефакторинг, переименование переменных, форматирование соседних файлов и «заодно починил ещё вот это» категорически запрещены.
3. **Обязательный regression-тест:** сначала зафиксируй воспроизведение инцидента тестом (Red), затем примени минимальный фикс (Green).
4. **Обратимость:** если hotfix затрагивает БД, миграция обязана иметь рабочий `downgrade()`.
5. **Повышенный уровень риска:** при любом сбое на hotfix действуй по `.agents/agents/error-handling.md`; severity по умолчанию — **High**, а если падает тест, который был зелёным до твоих правок — **Critical** (немедленный стоп и эскалация оператору).

## 2. Ворота перед коммитом и PR

- `uv run ruff check .`
- `uv run basedpyright`
- `uv run pytest -q`
- Чёткое описание причины инцидента, минимального фикса и плана отката в PR.
